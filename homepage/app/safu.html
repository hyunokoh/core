고객 자산 보호 펀드 (SAFU) Customer Asset Protection Fund

모든 거래 수수료의 10%가 자동으로 적립되어, 보안 사고·시스템 오류·청산 cascade로부터 사용자의 자산을 보전하는 자체 보험 펀드입니다. 잔액은 매 분 서명된 증명으로 공개되어 누구나 검증할 수 있습니다. 10% of every trading fee is automatically routed to a self-insurance fund that backstops users against security incidents, system errors and liquidation cascades. The balance is published every minute with an Ed25519-signed attestation that anyone can verify.

검증 / Verification

SAFU 잔액 attestation은 Ed25519 서명되어 있으며, 동일한 키가 PoL (Proof-of-Liabilities) 루트도 서명합니다. 외부 검증자는 단일 공개키만으로 두 가지 증명을 모두 확인할 수 있습니다. The SAFU attestation is Ed25519-signed with the same custodian key that signs PoL roots. An external verifier only has to trust one pubkey to audit both balances and liabilities.

서명 / Signature — 공개키 / Public key — 서명 스키마 / Scheme — 스냅샷 시각 / Snapshot at — PoL 키와 동일? / Shared with PoL? —
↓ attestation JSON 다운로드 / Download 🔑 서명 키 정보 / Signing key info → PoL 페이지 / Proof-of-Reserves
외부 검증용 Python 스니펫 / External verifier (Python, stdlib-only) 
# SAFU attestation verifier — copy & run, no pip deps required.
# python3 verify_safu.py
import hashlib, json, urllib.request

# Pure-Python Ed25519 (RFC 8032 ref impl) lives in tools/pol_server.py + safu_server.py.
# We assume it's available; if you only need to verify, lift those ~80 lines.
from safu_server import ed25519_verify  # ed25519_verify(pk: bytes, msg: bytes, sig: bytes) -> bool

URL = "https://api.zkcex.io/safu/attestation"  # or http://localhost:5500/safu/attestation in dev
data = json.load(urllib.request.urlopen(URL))

# Rebuild the canonical signed message — sort by_asset by 'asset', fold per-asset balances.
h = hashlib.sha256()
for a in sorted(data["by_asset"], key=lambda x: x["asset"]):
    h.update(f"{a['asset']}|{a['balance']}|{a['total_inflow']}|{a['total_payout']}\n".encode("utf-8"))
by_asset_hash = h.hexdigest()
t = data["totals"]
msg = (f"{data['scheme']}|{data['snapshot_at']}|{t['total_balance_usdt']}|"
       f"{t['total_inflow_usdt']}|{t['total_payout_usdt']}|{by_asset_hash}").encode("utf-8")

ok = ed25519_verify(bytes.fromhex(data["server_pubkey"]), msg, bytes.fromhex(data["signature"]))
print("SAFU attestation valid:", ok)
print("Total balance:        ", t["total_balance_usdt"], "USDT")
print("Open incidents:       ", t["n_incidents_open"])

작동 원리 / How it works

SAFU 펀드 운영 방식 / How the fund operates
  • 현물·선물 모든 거래에서 발생한 수수료의 10%가 자동으로 적립됩니다 / 10% of every spot and perpetual-futures fee is auto-routed into the fund.
  • 청산 cascade로 인한 잉여 마진의 일부도 함께 적립됩니다 / A slice of the surplus margin from liquidations also flows in.
  • 보안 사고, 시스템 오류, 청산 cascade가 발생하면 사용자 손실을 보전합니다 / Pays out to affected users in security breaches, system errors, or liquidation cascades.
  • 독립적인 ZK 증명으로 잔액을 누구나 검증할 수 있습니다 / Anyone can verify the balance via the signed attestation (Ed25519) above.
고지 / Disclaimer. 본 펀드는 자체 보험(self-insurance) 형태로 운영되며 정부 보증 또는 규제 보험 상품이 아닙니다. 지급 의무가 법적으로 보장되지 않으며, 펀드 잔액 한도 내에서 거래소의 재량으로 집행됩니다. This is a self-insurance fund operated by the exchange. It is NOT a regulator-approved or government-backed insurance product. Payouts are discretionary and capped at the fund's available balance.

자주 묻는 질문 / FAQ

SAFU 펀드는 어떻게 사용되나요? / When does the fund actually pay out?
보안 침해(키 유출, 스마트 컨트랙트 취약점), 거래소 측 시스템 오류(매칭 엔진 버그 등), 그리고 perp 청산이 cascade로 발전해 기존 insurance fund가 부족해진 경우에 사용됩니다. 모든 지급은 incident_id 단위로 추적되어 본 페이지에서 공개됩니다. Payouts cover security breaches (key compromise, contract exploits), our own system errors (matching-engine bugs, accounting glitches), and liquidation cascades that overwhelm the perp engine's own insurance bucket. Every payout is grouped under an incident_id, published on this page.
누가 관리하나요? / Who controls the fund?
펀드 잔액은 별도의 콜드 월렛에 보관되며(데모에서는 회계 장부로 운영), 지급은 거래소 보안팀의 다중 서명 승인을 필요로 합니다. 모든 지급 결정은 본 페이지의 "최근 사건" 섹션에 공개됩니다. The fund is held in a cold-stored wallet separate from the operational treasury. In this demo deployment it's accounted for in a dedicated ledger; in production the wallet would require multi-sig approval from the exchange security team for any debit. Every approval decision is published in the "Recent incidents" section above.
잔액을 어떻게 검증하나요? / How do I verify the balance?
위의 "검증" 섹션에서 attestation JSON을 다운받아 Ed25519 서명을 직접 확인하세요. 동일한 공개키가 PoL(Proof-of-Liabilities) 루트도 서명하므로, 키 하나만 신뢰하면 거래소의 부채 + SAFU 잔액을 모두 검증할 수 있습니다. Download the attestation from the Verification panel and run an Ed25519 verify against the published pubkey. The same key signs PoL roots, so you only need one trust anchor to audit both customer liabilities and the SAFU balance.
지급 한도가 있나요? / Is there a payout cap?
펀드 잔액 자체가 한도입니다. 잔액이 0이 되면 추가 지급이 불가합니다. 펀드는 매 거래 수수료의 10%로 지속 적립되므로, 거래량이 늘수록 한도도 함께 증가합니다. The cap is the fund balance itself. Once depleted, no further payouts can be made until new inflows accrue. Because 10% of every fee accrues continuously, the cap grows with trading volume.
다른 거래소의 보호 펀드와 무엇이 다른가요? / How is this different from other exchanges' funds?
대부분의 거래소 보호 펀드는 내부 회계 수치로만 공개됩니다. zkCEX SAFU는 모든 inflow가 on-ledger로 기록되고, 매 분 Ed25519 서명된 attestation으로 공개되며, 동일한 키가 부채 증명(PoL)을 서명하므로 잔액과 부채를 함께 검증할 수 있습니다. Most exchanges publish their protection fund as an internal accounting number. zkCEX SAFU publishes every inflow on a public ledger, mints a fresh signed attestation every minute, and uses the same custodian key as Proof-of-Liabilities — so a single key fully audits both balance and liability.
