Verifiable CEX backend

Binance-compatible REST + a real-time matching engine + 5-minute Proof-of-Liabilities + zkAML-driven deposit/withdraw decisions. Operators audit; users verify their own balance.

API docs Integration guide

Backend API + operator console. End-user trading UIs are built by integrators on top of this API.

Components

Binance-compatible REST

Standard surface (/v3/order, /v3/account, /v3/myTrades, /v3/depth, /v3/exchangeInfo, /v3/klines). Existing Binance clients (SDKs and bots) plug in unchanged.

Real-time matching engine

Kafka-driven order stream. GTC/IOC/FOK, MARKET orders, price/time priority, self-trade prevention (LIMIT and MARKET, both directions) — all covered end-to-end.

Proof-of-Liabilities (5-min epochs)

Per-user nonce + Merkle-sum tree lets every user verify locally that their balance is included in the published total liability. Exposed via /v3/pol/inclusion-proof.

Integrated AML (zkAML)

Every deposit and withdraw passes through zkAML for an ALLOW/REVIEW/BLOCK decision. Decisions are audit-logged; if zkAML is unreachable the system fails closed into the review queue.

Wallet + bc-gateway

Multi-chain deposits and withdrawals, address provisioning, transferRef de-duplication, and a tested withdraw state machine (CREATED → PROCESSING → DONE/REJECTED/CANCELED).

Observability

Spring Actuator, Prometheus metrics, structured logging, and Vault-backed secrets. A 25+ minute e2e validates correctness on every change.

Architecture

  1. API layer — api-binance-rest (Kotlin/Spring WebFlux). Surfaces the Binance-compatible endpoints to authenticated users.
  2. Matching gateway + engine — Kafka-routed orders and trades; supports per-market engine shards (matching-engine-duo).
  3. Wallet + Accountant — Balances, reservations, fees, transaction history. PostgreSQL persistence; restart resilience covered by e2e.
  4. bc-gateway — Synchronises deposits and withdrawals with external chains. Every deposit is recorded with its zkAML decision.
  5. Market — Public order book and recent-trades projections. Drives /v3/depth, /v3/ticker/24h, and /v3/klines.
  6. EventLog + zkPoL bridge — Streams balance deltas into the snapshot tree so a fresh PoL certificate is signed every five minutes.

Integrations

zkAML

Deposit/withdraw screening. Set ZKAML_ENABLED=true; default is fail-closed. Per-user audit rows, per-source sanctions freshness on /ops/readiness.

pol-snapshot-server

Ed25519-signed certificates over a Poseidon2 / Keccak256 Merkle-sum tree. Users verify locally with the @pol-snapshot/client SDK.

Keycloak / user management

Sign-up, email verification, OTP, sessions, and password reset all run through the standard Keycloak gateway.

Getting started

This is the operator/integrator backend. End-user trading UIs build on top of these APIs.

  1. Clone the repo: git clone https://github.com/zkrypto-inc/zkCEX
  2. Inside core/, run tools/e2e/run_exchange_e2e.sh --reset. The 25+ minute e2e brings up the full stack and validates every correctness scenario.
  3. Base URL: http://127.0.0.1:8094/v3/... (Binance-compatible). Auth uses X-Opex-User plus Binance-style HMAC SHA256.
  4. zkAML wiring: point app.zkaml.url at a running zkAML instance to gate deposits and withdrawals.
  5. PoL wiring: point app.pol.url at a running pol-snapshot-server so /v3/pol/inclusion-proof can return per-user balance proofs.

See docs/exchange-e2e.md in the repo for the full operator runbook.
