검증 가능한 CEX 백엔드

Binance-compatible REST + 실시간 매칭 엔진 + 5분 주기 Proof-of-Liabilities + zkAML-driven 입출금 결정. 운영자가 감사하고, 사용자가 자신의 잔고를 직접 검증합니다.

API 문서 통합 가이드

백엔드 API + 운영자 콘솔. 트레이딩 UI는 통합 파트너가 별도로 구축합니다.

제품 구성

Binance 호환 REST

/v3/order, /v3/account, /v3/myTrades, /v3/depth, /v3/exchangeInfo, /v3/klines 등 표준 API 표면. 기존 Binance 클라이언트(SDK/봇)를 그대로 연결할 수 있습니다.

실시간 매칭 엔진

Kafka 기반 주문 스트림, GTC/IOC/FOK, MARKET 주문, 가격/시간 우선순위, self-trade prevention(LIMIT/MARKET 양방향)이 e2e로 검증되어 있습니다.

Proof-of-Liabilities (5분 epoch)

per-user nonce + Merkle-sum tree로 사용자가 자신의 잔고가 거래소 총 부채에 포함되어 있음을 직접 검증합니다. /v3/pol/inclusion-proof로 노출.

통합 AML (zkAML)

입금/출금마다 zkAML이 ALLOW/REVIEW/BLOCK 결정을 반환. 모든 결정은 audit log에 기록되며, zkAML 미가용 시 fail-closed로 REVIEW 큐에 보관됩니다.

지갑 + bc-gateway

다중 체인 입출금, 주소 발급, transferRef 중복 거부, withdraw 상태 머신(CREATED → PROCESSING → DONE/REJECTED/CANCELED)이 단위·통합 테스트로 보장됩니다.

관측성

Spring Actuator, Prometheus 메트릭, structured logging, Vault 기반 시크릿 관리. 25+ 분 짜리 e2e가 매 변경마다 correctness를 검증합니다.

아키텍처 스택

  1. API 계층 — api-binance-rest (Kotlin/Spring WebFlux). 인증된 사용자에게 Binance-호환 endpoint 제공.
  2. Matching gateway + engine — Kafka로 주문/체결을 라우팅, market 별 분리된 engine shard 지원 (matching-engine-duo).
  3. Wallet + Accountant — 잔고/예약, 수수료, 트랜잭션 히스토리. PostgreSQL에 영속, 재시작 후 매칭 가능한 상태 유지가 e2e로 검증됨.
  4. bc-gateway — 외부 체인과 입출금 동기화. 모든 deposit이 ALLOW/REVIEW/BLOCK 감사 row로 기록됨.
  5. Market — 공개 주문서/최근 거래 projection. /v3/depth, /v3/ticker/24h, /v3/klines 출력.
  6. EventLog + zkPoL bridge — 잔고 변동을 Merkle-sum 스냅샷에 공급해 5분마다 PoL certificate 발행.

통합

zkAML

입출금 screening 전담. ZKAML_ENABLED=true로 활성화, 기본 fail-closed. 사용자별 audit row + per-source sanctions 신선도 모니터링.

pol-snapshot-server

Ed25519 서명 인증서 + Poseidon2/Keccak256 Merkle-sum tree. 사용자가 client SDK(@pol-snapshot/client)로 자신의 inclusion proof를 직접 검증.

Keycloak / 사용자 관리

가입, 이메일 인증, OTP, 세션, 비밀번호 재설정이 standard Keycloak gateway를 통해 처리됩니다.

시작하기

운영자/통합 파트너용 백엔드 스택입니다. 사용자 트레이딩 UI는 별도 프론트엔드에서 이 API를 호출해 구성합니다.

  1. 저장소 clone: git clone https://github.com/zkrypto-inc/zkCEX
  2. core/로 이동, tools/e2e/run_exchange_e2e.sh --reset 실행. 25+ 분 e2e가 전체 스택을 띄우고 모든 correctness 시나리오를 검증합니다.
  3. API 베이스: http://127.0.0.1:8094/v3/... (Binance 호환). 인증은 X-Opex-User 헤더 + 표준 HMAC SHA256 (Binance 방식).
  4. zkAML 통합: app.zkaml.url로 zkAML 인스턴스를 가리키면 입출금이 자동으로 screening됨.
  5. PoL: app.pol.url로 pol-snapshot-server를 가리키면 /v3/pol/inclusion-proof가 사용자별 잔고 증명을 반환.

상세 운영 가이드는 저장소의 docs/exchange-e2e.md를 참고하세요.
